# ADR-001 — مونولیت ماژولار به‌جای میکروسرویس

- وضعیت: پذیرفته‌شده (پایه معماری)
- تاریخ: ۱۴۰۵/۰۶/۰۵
- مرتبط: سند اصلی فصل ۴، گزارش ممیزی یافته B1

## زمینه

سند مرجع (ideaone) معماری میکروسرویسی با Module Federation، K8s و RabbitMQ را پیشنهاد داده بود. ممیزی سندباکس نشان داد ۷ شکاف بنیادین (از جمله نبود زیرساخت ارکستراسیون، پیام‌ساز و observability) مانع پیاده‌سازی وفادار آن معماری است؛ همزمان تیم توسعه (عامل‌محور) کوچک است و هزینه هماهنگی میکروسرویس توجیه ندارد.

## تصمیم

۱. کل سامانه یک **مونولیت Next.js واحد** است با مرزبندی سخت‌گیرانه در سطح پوشه:
   - `src/core/*` — زیرساخت مشترک (auth، tenancy، events، notifications، audit، shared)
   - `src/modules/<domain>/*` — ماژول کسب‌وکار مستقل (service + components)
   - `src/app/api/**` — آداپتور نازک HTTP (بدون منطق)
۲. جایگزینی Module Federation با **رجیستری ماژول دیتابیس‌محور** (ADR-002 در سند اصلی: جدول‌های `PlatformModule` + `ModuleActivation`) — سایدبار و دسترسی‌ها از دیتابیس ساخته می‌شوند.
۳. ارتباط بین‌ماژولی فقط از طریق **Outbox** (ADR-003) — import مستقیم ماژول از ماژول ممنوع.
۴. تنها سرویس جداگانه: مینی‌سرویس‌های Bun در `mini-services/` برای نیازهای stateful مثل WebSocket.

## پیامدها

✅ استقرار تک‌پروسه‌ای سازگار با سندباکس · وابستگی جهت‌دار و قابل lint · مسیر مهاجرت آینده به میکروسرویس از مرزهای موجود · سادگی دیباگ
❌ نظم پوشه باید با بازبینی کد حفظ شود (ریسک نشت منطق به route ها) · الزام ADR-003 برای جلوگیری از coupling پنهان
