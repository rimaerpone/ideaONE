# ADR-003 — الگوی Outbox برای رویدادهای دامنه

- وضعیت: پذیرفته‌شده
- تاریخ: ۱۴۰۵/۰۶/۰۵
- مرتبط: سند اصلی فصل ۹ (Event Bus)، ممیزی یافته B2

## زمینه

سند مرجع RabbitMQ/Kafka برای رویدادهای دامنه پیشنهاد داده بود. سندباکس message broker ندارد؛ همزمان نیاز واقعی امروز فقط «ثبت رویداد برای حسابرسی/پردازش بعدی» است، نه pub/sub زنده.

## تصمیم

۱. جدول `OutboxEvent (id, type, payload, createdAt, processedAt?)` در همان SQLite.
۲. تابع واحد `emitEvent(type, payload)` در `core/events` — همیشه **داخل همان تراکنش منطقی** عملیات کسب‌وکار صدا زده می‌شود (نوشتن atomic).
۳. هیچ side-effect فوری به Outbox گره نمی‌خورد؛ پردازش دوره‌ای (worker آینده) رویدادهای `processedAt=null` را مصرف می‌کند.
۴. اعلان کاربر **نباید** از Outbox تبعیت کند — تحویل فوری از `notify()` می‌گذرد (ADR-004)؛ Outbox مخصوص رویدادهای دامنه/حسابرسی است.

## پیامدها

✅ بدون زیرساخت اضافه · atomic با عملیات اصلی · مشاهده‌پذیر در UI تنظیمات · مسیر ارتقا به broker واقعی (نوع رویدادها ثابت می‌ماند)
❌ پردازش دوره‌ای هنوز دستی/نیمه‌خودکار است (ریسک انباشت — در داشبورد تنظیمات شمارش دیده می‌شود) · ترتیب مصرف تضمین‌شده نیست (id سفارشی مصرف‌کننده اعمال می‌کند)
