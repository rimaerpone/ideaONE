# ADR-006 — نظام مستندسازی مهندسی‌شده

وضعیت: پذیرفته شده | تاریخ: ۱۴۰۵/۰۶/۰۵ | مرتبط: AGENTS.md · docs/README.md

## زمینه

فاز پایلوت با مستندات سطح نمای کلی (۴ سناریوی کوتاه + ۵ ADR) بسته شد. بازخورد صریح ذی‌نفع: «سناریوها بسیار ساده‌اند؛ هیچ اثری از اطلاعات هر فرم و هر ماژول نیست؛ مستندات باید آنقدر دقیق باشند که مسیر روشن باشد و فرانت‌اند ساده طراحی نشود». ریشه مشکل: نبود **قانون نگهداشت سند** و نبود **قالب مشخصات سطح جزئیات (SPEC)**.

## تصمیم

۱. **ساختار هشت‌گانه docs/** با نقشه واحد `docs/README.md`:
`product/` (چیستی/برای‌کی) · `architecture/` (چگونگی) · `modules/` (SPEC ماژول‌ها) · `scenarios/` (رفتار عملیاتی) · `roadmap/` (مسیر) · `adr/` (چرا) · `runbook/` (عملیات) · `persian/` (فارسی/انطباق).

۲. **قالب SPEC الزامی** (`modules/_TEMPLATE.md`): هر ماژول باید ماتریس مجوز، مدل داده، نماها ستون‌به‌ستون، فرم‌ها فیلد‌به‌فیلد (ویجت/لیبل/الزامی/اعتبارسنجی/پیش‌فرض/رفتار شرطی)، گردشکار، API با خطاهای دقیق فارسی، اعلان‌ها و شکاف‌های v1 با ارجاع وظیفه نقشه راه داشته باشد.

۳. **قواعد نگهداشت**:
- سند در همان PR تغییر رفتاری به‌روزرسانی می‌شود (بدون سند، PR رد).
- هر سند وضعیت/مالک/تاریخ بازنگری دارد.
- شکاف‌های v1 حذف نمی‌شوند؛ تا بسته شدن با وظیفه نقشه راه لینک می‌مانند.
- نام فایل سناریو/ADR ثابت است چون کد به آن‌ها ارجاع می‌دهد.

۴. **نقشه راه وظیفه‌محور**: شناسه پایدار `Pn-Tkk` + معیار پذیرش + وابستگی + وضعیت؛ ارجاع در کامنت کد (`TODO(Pn-Tkk)`) و کامیت‌ها مجاز.

۵. **راستی‌آزمایی اعداد**: هر عدد ادعاشده در مستندات باید قابل شمارش از منبع باشد (نمونه: شمارش ۲۸۴ وظیفه با اسکریپت از روی شناسه‌ها).

## پیامدها

- **مثبت**: مسیر توسعه برای هر عامل/توسعه‌دهنده تازه از مستندات قابل استخراج است؛ طراحی فرانت‌اند از SPEC فیلد‌به‌فیلد شروع می‌شود نه از حدس؛ برآورد فازها واقعی می‌شود.
- **منفی**: هزینه نگهداشت — هر PR کمی کندتر؛ با چک‌لیست PR جبران می‌شود.
- **ریسک**: کهنگی سند اگر قانون «همان PR» اجرا نشود؛ کنترل: بازبینی فصلی + وضعیت سند.

## گزینه‌های ردشده

- مستند در ویکی بیرونی: از مخزن جدا می‌افتد و نسخه‌بندی نمی‌شود.
- مستند در کد فقط (TSDoc): جدول‌های مجوز/سناریو در کد خوانا نیست.
- نگه‌داشتن سطح قبلی: دیده شد که به طراحی ساده منجر می‌شود (خودِ زمینه این ADR).
