# ADR-007 — استانداردهای اجرایی: دروازه کیفیت check

وضعیت: پذیرفته شده | تاریخ: ۱۴۰۵/۰۶/۰۶ | مرتبط: AGENTS.md · 02-folder-structure · 07-conventions · RB-01

## زمینه

ممیزی ساختار مخزن (۱۴۰۵/۰۶) نشان داد قواعد مستندِ خوب، بدون اجرای ماشینی می‌پوسند. در لحظه ممیزی این واگرایی‌ها بین «سند» و «واقعیت» وجود داشت:

| یافته | نوع |
|---|---|
| ۲۹ کامپوننت ui بلااستفاده (کد مرده) + ۳۶ وابستگی npm یتیم/شبح | فایل منسوخ |
| `ServiceResult` در letters تعریف شده و ۶ ماژول دیگر از آنجا import می‌کردند (نقض مرز ماژول) | مرز معماری |
| ۵ route (۴ auth + اعلان‌ها) منطق کسب‌وکار و Prisma مستقیم داشتند (تا ۳۲ خط) | route نازک |
| `tailwind.config.ts` پیکربندی مرده Tailwind 3 (نسخه 4 فقط globals.css را می‌خواند) | فایل منسوخ |
| `react-date-object` و `server-only` بدون اعلام در package.json (وابستگی شبح) | بهداشت وابستگی |
| ادعای «۲۲ مدل» در docs/README در برابر ۲۱ مدل واقعی؛ «۳۴۸ وظیفه» در P0-T6 در برابر ۲۸۴ واقعی | عدد غیرواقعی |
| مسیر `realtime.log` در دو سند متفاوت؛ ادعای غلط درباره gitignore لاگ‌ها | سند ناهم‌خوان |
| `.env` track شده در تضاد با الگوی `.env*`؛ پوشه `.zscripts/` محیطی مستند نشده بود | سند ناقص |
| ۴ کامیت با پیام UUID در تاریخچه (نقض Conventional) | حکمرانی |

ریشه مشکل واحد بود: **بررسی صحت سندها و ساختار به حافظه و دقت انسانی/عاملی واگذار شده بود.**

## تصمیم

۱. **دروازه کیفیت واحد**: `scripts/check.ts` با فرمان `bun run check` — ۱۸ بررسی (CH-01..CH-18) در هفت گروه: آناتومی ساختار، مرزهای معماری، وابستگی‌ها (استفاده/شبح/allowlist مستند)، فایل‌های مرده (بسترسازی ترانزیتیو از نقاط ورود)، صحت مستندات (پیوندها، نام‌گذاری، اعداد ادعاشده در برابر منبع)، رجیستری↔کد، و هشدارهای عملیاتی. هر خطا = exit 1.

۲. **قاعده طلایی**: هر قاعده مستندِ قابل‌اتوماسیون باید هم‌زمان یک بررسی CH-xx در دروازه بیاید؛ افزودن قاعده به 02-folder-structure بدون بررسی ماشینی، PR را رد می‌شود.

۳. **allowlist صریح وابستگی‌ها**: هر dependency بلااستفاده فقط با پیوند نقشه راه/ADR در `DEP_ALLOWLIST` می‌ماند (وضعیت فعلی: react-query/react-table ← P1، react-hook-form + zod ← P1-T20، prisma ← CLI، react-dom ← peer).

۴. **حکمرانی اعداد**: هر عدد ادعاشده در مستندات (شمار مدل، شمار وظیفه هر فاز و جمع کل) ماشینی با منبع (schema.prisma، فایل‌های roadmap) مقایسه می‌شود (CH-14/CH-15).

۵. **دروازه در چرخه کامیت**: چک‌لیست PR در AGENTS.md با `bun run check` آغاز می‌شود؛ RB-01 هم سلامت مخزن را با آن می‌سنجد.

## پیامدها

- **مثبت**: واگرایی سند↔کد حداکثر در یک کامیت کشف می‌شود (نه یک فاز)؛ «هر فایل هدف دارد» از شعار به بررسی گراف دسترسی تبدیل شد؛ اعداد مستندات قابل اتکا شدند؛ بازنگری فصلی مستندات ارزان شد.
- **منفی**: هزینه نگهداشت دروازه (هر قاعده جدید ~۱۵ خط TS)؛ رشته‌هشدارهای عملیاتی باید ماهانه مرور شوند.
- **ریسک**: false-positive در بررسی‌های مبتنی بر regex (import/لینک) — کاهش: الگوهای محافظه‌کارانه + exempt مشخص (worklog سند تاریخی است و ممیزی نمی‌شود).

## گزینه‌های ردشده

- **eslint-plugin-boundaries / dependency-cruiser**: ابزار خارجی جدید + اجرای جداگانه؛ دروازه واحدِ Bun بدون وابستگی جدید سبک‌تر و با سند فارسی هم‌راستا است (ممنوعیت اختراع چرخ در سندباکس).
- **CI گیت ریموت**: مخزن محلی بدون remote؛ دروازه محلی جایگزین آن است.
- **بازبینی دستی در review**: همان چیزی که موجب ۹ یافته ممیزی شده بود.
