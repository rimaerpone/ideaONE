# ADR-009 — تکمیل سرویس‌های هسته (۶ سرویس غایب سند منبع ۵.۱)

- وضعیت: پذیرفته‌شده
- تاریخ: ۱۴۰۵/۰۶/۱۳
- مرتبط: ADR-001، ADR-003 (Outbox)، ADR-005 (قواعد سندباکس) · سند منبع بخش ۵.۱ (۱۸ سرویس هسته) · بسته P0-T14/T18/T19

## زمینه

سند منبع ۱۸ سرویس هسته تعریف می‌کند. پیاده‌سازی تا این نقطه ۶ زیرسیستم داشت (auth، tenancy، events، notifications، audit، shared)؛ شش سرویس زیر غایب بودند و دو وظیفه باز P0 (پردازشگر Outbox و پایش دوره‌ای) نیز به همان‌ها گره خورده بود: Feature Flags، Storage، Scheduler، AI Gateway، Integration Bus، Reporting Metadata.

## تصمیم

هر شش سرویس با «قرارداد استقرار-پذیر» در `src/core/` پیاده شدند — یعنی رفتار امضادهنده ثابت و آداپتر سندباکس قابل تعویض:

| سرویس | مسیر | آداپتر سندباکس | مسیر استقرار تولیدی | مدل داده |
|---|---|---|---|---|
| Feature Flags (سرویس ۱۳) | `core/featureflags` | جدول DB + کش ۱۵ث | همان + UI عملیات | `FeatureFlag` |
| File & Document Storage (۱۱) | `core/storage` | فایل‌سیستم `.storage/` | S3/MinIO با همان قرارداد putObject/getObject | `FileObject` + `Attachment` (چندریختی) |
| Scheduler / Background Jobs (۱۲) | `core/scheduler` + `src/instrumentation.ts` | حلقه ۱۵ثانه درون‌فرایندی + global guard | کارگر جدا / cron | `ScheduledJob` |
| AI Gateway (۱۷) | `core/ai/gateway` | z-ai-web-dev-sdk | هر LLM سازمانی | `AiInvocation` (تلمتری، بدون FK عمدی) |
| Integration Bus (۱۸) | `core/integration` | کاتالوگ کانکتور (حاکمیت «اول ثبت، بعد اتصال») | کانکتورهای واقعی P2+ | `IntegrationConnector` |
| Reporting Metadata (۱۶) | `core/reporting` | کاتالوگ ۱۲ گزارش استاندارد | موتور اجرا + BI (P6) | `ReportDefinition` |

قواعد حاکم:
۱. **AI Gateway تنها نقطه ورود مدل زبانی است** — هر فراخوانی گیت فلگ اختصاصی + سجل تلمتری (وظیفه/تأخیر/نتیجه) + تایم‌اوت دارد؛ سیاست‌های داده (مثل محرومیت نامه سری) در ماژول کسب‌وکار می‌مانند.
۲. **زمان‌بند از instrumentation بوت می‌شود** (یک‌بار per فرایند، خاموشی اضطراری با `SCHEDULER_DISABLED=1`)؛ تعریف کارها در DB است و دو کار اولیه دارد: `outbox-processor` (بسته P0-T18) و `health-monitor` (P0-T14).
۳. **پیوست چندریختی** (`Attachment`: entityType+entityId) — نامه اولین مصرف‌کننده است؛ بایگانی دیجیتال و قراردادها بدون تغییر قرارداد اضافه می‌شوند.
۴. **قابلیت واقعی = فلگ واقعی**: سه پرچم اولیه (`ai.letter-assist`، `storage.letter-attachments`، `scheduler.enabled`) همگی مسیر کد واقعی را قطع/وصل می‌کنند و در تب «پرچم‌های ویژگی» توسط مدیر قابل تغییرند.

## پیامدها

✅ پوشش ۱۸/۱۸ سرویس هسته سند منبع · P0-T14/T18/T19 بسته شد (رویدادهای Outbox ظرف حداکثر ۶۰ ثانیه «تحویل‌شده» می‌شوند و در تب رویدادها دیده می‌شود) · ممیزی مصرف AI با تأخیر واقعی · مهاجرت به S3/کرون/LLM دیگر بدون تغییر ماژول‌ها
❌ زمان‌بند درون‌فرایندی تک‌نمونه است (کافی برای پایلوت؛ استقرار چندنمونه نیازمند قفل توزیع‌شده دارد — P7) · کانکتورها فعلاً «برنامه‌ریزی‌شده»اند و اتصال زنده ندارند (صادقانه در UI نمایش داده می‌شود)

## جهت enforcing

- CH-02 دروازه (server-only) برای همه فایل‌های جدید برقرار است
- مشاهده‌پذیری: تب «تنظیمات ← یکپارچه‌سازی و گزارش‌ها» وضعیت هر دو کار زمان‌بند + سجل ۳۰ فراخوانی اخیر AI را نشان می‌دهد
