# امنیت، کنترل دسترسی و ایزولاسیون چندشرکتی

وضعیت: **فعال** | مالک: معماری/امنیت | بازنگری: ۱۴۰۵/۰۶/۰۵ | پیوند: ADR-002، ADR-004

## ۱. احراز هویت

| مؤلفه | پیاده‌سازی | فایل |
|---|---|---|
| هش رمز | scrypt با salt تصادفی (بدون کتابخانه خارجی) | `core/auth/auth.ts` |
| نشست | رکورد `Session` در DB؛ **شناسه نشست داخل کوکی httpOnly** (بدون expose به JS) | همان |
| عمر | ۳۰ روز؛ پاکسازی تنبل رکوردهای منقضی هنگام هر `requireCtx` | همان |
| ورود | `POST /api/auth/login` — پیام خطای عمومی «نام کاربری یا گذرواژه نادرست» (بدون افشای اینکه کدام فیلد غلط است) | `api/auth/login/route.ts` |
| خروج | `POST /api/auth/logout` — حذف رکورد نشست + پاک‌سازی کوکی | همان پوشه |
| کاربر غیرفعال | `isActive=false` → ورود رد می‌شود، در فهرست ارجاع نمی‌آید | سرویس‌ها |

`requireCtx()` قرارداد همه routeهاست: بدون نشست معتبر → 401 فارسی؛ خروجی `SessionContext { userId, companyId }`.

## ۲. ایزولاسیون چندشرکتی (ADR-002)

- **منبع حقیقت مالکیت**: فیلد `companyId` روی هر رکورد عملیاتی (Letter، WarehouseDoc، GoodsRequest، Product، PartnerInstance، DocCounter).
- **دامنه دید** = `scopeCompanyIds(ctx)` (`core/tenancy/tenancy.ts`):
  - شرکت فعال GROUP → همه companyIdهایی که کاربر عضو است (دید هلدینگی تجمعی).
  - شرکت فعال COMPANY → فقط همان شرکت.
  - بدون شرکت فعال → آرایه خالی (هیچ داده‌ای دیده نمی‌شود).
- **قاعده طلایی کوئری**: هر `findMany/findFirst` در سرویس‌ها باید `companyId: { in: scopeIds }` (یا مساوی شرکت فعال) داشته باشد. review بدون این فیلتر رد می‌شود.
- **نوشتن فقط در شرکت فعال**: اگر شرکت فعال GROUP باشد، ثبت رکورد عملیاتی با خطای «به شرکت عملیاتی سوئیچ کنید» رد می‌شود.
- **مالکیت مرجع‌ها**: محصول/انبار انتخابی در فرم باید `companyId === ctx.companyId` باشد (بررسی صریح در سرویس انبار/درخواست).
- **ارجاع نامه**: گیرنده باید عضو یکی از شرکت‌های دامنه دیدِ نامه باشد.

## ۳. نقش‌ها و ماتریس دسترسی

نقش‌ها در بستر `Membership.role` (per-company) + `User.isAdmin` (پلتفرمی):

### تعریف نقش‌ها

| نقش | قلمرو | فلسفه |
|---|---|---|
| ADMIN | شرکت (یا هلدینگ) | مدیریت کامل + تنظیمات؛ تنها نقش با toggle ماژول شرکتی |
| MANAGER | شرکت | تصمیم‌گیر گردشکارها (تأیید/رد درخواست، تأیید نامه) |
| OPERATOR | شرکت | ثبت و اقدام روی اقلام خودش |
| VIEWER | شرکت | فقط مشاهده (امروز: منو/فهرست‌ها؛ اعمال سلبی کامل در P1-T31) |
| isAdmin (User) | پلتفرم | toggle سراسری ماژول + دید تنظیمات |

> P1-T18 بسته شد: **هیچ endpoint نوشتاری برای VIEWER باز نیست** — گارد سرور `requireWriteRole` (دیفنس اول) + پنهان‌سازی دکمه‌های ثبت با هوک `useCanWrite` (دیفنس دوم/UX).
>
> **P1-T31 بسته شد (۱۴۰۵/۰۶/۲۹)**: ماتریس متقاطع کامل با ۱۰۳ سنجه در `scripts/test-rbac.ts` خودکار تست می‌شود (سه اجرای متوالی سبز) — شامل گشت‌های تازه: toggle ماژول و تغییر تنظیمات برای VIEWER (403)، دید per-company درخواست، اعلان سقف‌دار، و گارد API سطح ماژول.
>
> **P1-T28 — گارد API سطح ماژول**: ماژول خاموش (سراسری یا شرکتی) → همه APIهای آن ماژول 404 فارسی («این قابلیت برای شرکت فعال شما فعال نیست…») — ۱۴ مسیر: letters×4 + attachments + whdocs×3 + requests×2 + stock + warehouses + products + partners. کش سینگلتون globalThis (`core/tenancy/module-access.ts`)؛ toggle بلافاصله بی‌اعتبرش می‌کند (سنجه SC-008 ≤ ۲s). مدیر پلتفرم بای‌پس ندارد — آینه منطق منو؛ رجیستری ماژول‌ها (خودش بدون گارد) زنده می‌ماند = مسیر بازگشت همیشه باز.

## ۴. بلادرنگ — بلیت HMAC (ADR-004)

```
GET /api/realtime/ticket  (کوکی نشست الزامی)
   → ticket = base64(userId:exp).hmac_sha256(REALTIME_SECRET, ttl=60s)
کلاینت → io('/?XTransformPort=3003') + emit('register', ticket)
سرویس  → timingSafeEqual(هش) → join('user:<id>') · رد با disconnect
```

- بلیت **یک‌بارمصرف نیست اما ۶۰ ثانیه‌ای است** و فقط userId امضاشده حمل می‌کند (نه داده).
- شنود متقابل ممکن نیست: هر کاربر فقط اتاق خودش؛ emit داخلی با `x-internal-key` روی `127.0.0.1:3004` فقط از لوکال‌هاست.
- کلید مشترک از متغیر محیطی مینی‌سرویس؛ هرگز به کلاینت نمی‌رود.

### گاردهای نقش مشترک (P1-T14/T18/T28 — `core/tenancy/tenancy.ts` + `core/shared/server-helpers.ts`)

| گارد | منطق | پیام رد (فارسی) |
|---|---|---|
| `requireWriteRole(ctx)` | isAdmin بای‌پس؛ ADMIN/MANAGER/OPERATOR مجاز | «نقش «بازدیدکننده» اجازه ثبت یا تغییر داده ندارد…» — 403 |
| `requireSettingsAdmin(ctx)` | isAdmin یا ADMIN شرکت فعال | «دسترسی به تنظیمات بستر فقط برای مدیران سامانه مجاز است» — 403 |
| `requireModule(code)` (P1-T28) | احراز هویت + ماژول فعال سراسری و شرکتی | «این قابلیت برای شرکت فعال شما فعال نیست؛ برای فعال‌سازی با مدیر سامانه تماس بگیرید» — 404 |

قاعده: هر سرویس نوشتاری جدید با `requireWriteRole` شروع می‌شود؛ هر route ماژول عملیاتی جدید با `requireModule(code)` شروع می‌شود (نگاشت code: office-automation / warehouse / products / partners)؛ آینه کلاینت = هوک `useCanWrite` (دکمه‌ها مخفی، نه فقط disable — پنهان‌سازی به‌تنهایی مجاز نیست و سرور حاکم است).

⚠️ درس dev: کش درون‌فرایندی برای stateهای مشترک بین routeها باید سینگلتون globalThis باشد — در حالت dev هر route نمونه جدا از ماژول دارد و invalidate فقط کشِ همان route را پاک می‌کند (باگ P1-T28 در اولین اجرای تست).
