## ۱. هرم تست (واقع‌بینانه برای سندباکس)

| سطح | ابزار | چه چیزی | چه زمانی |

| یکه | تست اسکریپتی (مثل `scripts/test-jalali.ts`) | منطق‌های خالش حساس (تبدیل تاریخ، الگوریتم‌ها) | بعد از تغییر همان منطق |

| لاگ | `tail dev.log` (Next) + `realtime.log` | خطاهای سرور | پایان هر تسک |

- seed کامل: ۵ شرکت، ۸ کاربر، ۱۶ ماژول، ۱۱ محصول، ۸ شریک، ۵ انبار (لیان با seed:big تکمیل می‌شود)، ~۳۰ واریانت، ۱۰+ سند، ۵ درخواست، ۱۴ نامه.
- حساب‌ها: admin/admin123 · ceo.arad|dabir.arad|anbar.arad با 12345678.
- seed قابل تکرار: `bunx tsx scripts/seed.ts` (پاک‌سازی کامل — فقط در محیط دمو).
- **داده حجمی کارایی (P1-T10):** `bun run seed:big` — ۱۰٬۰۰۰ نامه/۵٬۰۰۰ سند/۵۰۰ کالا/۲٬۰۰۰ درخواست/۳٬۰۰۰ سجل/۱۲۰ شریک در ~۳ث؛ توزیع وزنی بین شرکت‌ها و ~۵۵٪ در ۴۵ روز اخیر (روند داشبورد واقعی)؛ شماره‌ها از DocCounter ادامه می‌یابند؛ اجرای مجدد = افزودن مجدد. برای بازتنظیمی: seed اصلی و سپس seed:big.
- **تست کارایی (P1-T10/T11):** `bunx tsx scripts/test-perf.ts` — بودجه داشبورد <۵۰۰ms و همه فهرست‌ها <۱s (میانه ۳ اجرا پس از گرم‌کردن؛ صفحه عمیق ~۱۰هزارم شامل می‌شود) · `bun scripts/test-indexes.ts` — EXPLAIN QUERY PLAN هر ۱۹ مسیر طلایی باید SEARCH USING INDEX باشد (نه SCAN)؛ استثنای مستند: جمع کامل StockItem.
