# قالب SPEC ماژول — همه مشخصات ماژول‌ها با این ساختار نوشته می‌شود

> هنگام ایجاد SPEC جدید، این قالب را کپی کنید و همه بخش‌ها را پر کنید.
> بخش بی‌محتوا نداشته باشد: اگر چیزی «نداریم»، همان‌جا بنویسید «نداریم (→ Pn-Tkk)» با ارجاع وظیفه نقشه راه.

```markdown
# SPEC — <نام ماژول>

وضعیت: فعال/غیرفعال | نسخه: v1.0 | کد رجیستری: `<code>` | مالک: <نقش>
تاریخ بازنگری: ۱۴۰۵/… | پیوندها: سناریو SC-NNN · نقشه راه Pn

## ۱. هدف و دامنه
- مسئله‌ای که حل می‌کند (۱ بند) + «خارج از دامنه» (فهرست صریح با ارجاع فاز آینده)

## ۲. بازیگران و ماتریس مجوز
| عملیات | ADMIN | MANAGER | OPERATOR | VIEWER | نقطه اجرای مجوز (فایل/تابع) |

## ۳. مدل داده
فیلدهای اختصاصی ماژول (برای کل مدل: پیوند به architecture/03-data-model.md)
+ اینواریانت‌ها و قواعد سلبی

## ۴. نماها (Views)
برای هر نما: مسیر/ورودی · فیلترها و تب‌ها · ستون‌ها/کارت‌ها (جدول: عنصر، نوع، رفتار) ·
عملیات ردیفی/سرصفحه · مرتب‌سازی/صفحه‌بندی · حالت خالی/بارگذاری/خطا · موبایل

## ۵. فرم‌ها (Forms)
برای هر فرم — جدول فیلد‌به‌فیلد:
| فیلد | ویجت | لیبل | الزامی | اعتبارسنجی (کلاینت/سرور) | پیش‌فرض | رفتار شرطی |
+ دکمه‌ها/اقدامات · پیام‌های موفق/خطا (متن دقیق فارسی) · رست بعد از ثبت

## ۶. گردشکار (ماشین حالت)
حالت‌ها + گذارهای مجاز + نگهبان‌ها + عوارض جانبی هر گذار (notify/audit/outbox)

## ۷. API
| متد مسیر | ورودی | خروجی | خطاها | مجوز |

## ۸. اعلان‌ها و رویدادها
متن دقیق اعلان‌ها (title/body/نوع/مقصد) + رویدادهای Outbox

## ۹. متن‌ها و لیبل‌ها
enum → لیبل فارسی (تک منبع حقیقت برای UI)

## ۱۰. موبایل و دسترس‌پذیری

## ۱۱. شکاف‌های v1 و الزامات نسخه بعد
| شکاف | اثر کاربری | راه‌حل | وظیفه نقشه راه |
```

## قواعد نگهداشت SPEC

1. هر PR که رفتار ماژول را عوض کند، SPEC همان ماژول در همان PR به‌روزرسانی می‌شود.
2. «شکاف‌های v1» هرگز حذف نمی‌شوند تا بسته شوند؛ فقط وضعیت (باز/بسته) عوض می‌شود.
3. جداول ستون/فیلد باید با کدِ واقعی (نه آرزوها) مطابق باشند؛ موارد آینده با علامت (Pn) متمایز می‌شوند.
4. متن‌های فارسی (خطا/اعلان/لیبل) دقیقاً همان رشته‌های کد نقل می‌شوند.
```
