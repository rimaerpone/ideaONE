## ۱. خلاصه مدیریتی

- **اسکلت تب‌محور از قبل وجود دارد و درست کار می‌کند**: نوار تب مرورگون (P1.5) با dedup، تب رکورد/فرم جدید، بستن با کلیک‌وسط، ماندگاری sessionStorage؛ قالب صفحه رکورد با تب داخلی (RecordPageShell)؛ پنل پیش‌نمایش کنار فهرست (P2.5-U4). این پاسخ به «تب اصلی که تب‌ها را نمایش می‌دهد» است — **باید حفظ و تعمیق شود، نه بازطراحی**.
- **«نصف بودن صفحه در دسکتاپ» سه تفسیر ممکن دارد** (§۳): نیم‌صفحه لیست+رکورد همزمان (FCL) / فرم دوسطونه / بهینه برای پنجره نیم‌عرض. توصیه: **F Fiori Flexible Column تکمیل‌شده با عرض مذاکره‌پذیر نیم→کامل** (U9) چون هر سه خواسته «اطلاعات بیشتر در قاب» را پاسخ می‌دهد.
- **تب داخلی فقط در ۲ صفحه از ~۱۵ صفحه رکورد واقعی استفاده می‌شود** (نامه، کاربر) — استانداردسازی الگوی «چه تب‌هایی، با چه ترتیبی، با چه شمارنده‌ای» لازم است (U10).
- **نظام پوسته ظاهری در نقشه راه نبود** — فاز جدید **P2.8 (۹ وظیفه)** ساخته شد: تم روشن/تاریک، رنگ سازمانی per-company، تراکم/فونت per-user (G11 بنچمارک)، کنتراست بالا، کاهش حرکت، پوسته چاپ.
- **ماندگاری نشست**: راه‌حل قطعی = GitHub (کد) + Neon (دیتابیس) — معماری و پروتکل در §۷.

## ۵. نظام پوسته ظاهری (۱۰ پیشنهاد + معماری)

### معماری پیشنهادی — توکن‌های سه‌لایه

```
لایه ۱ (خام)     : پالت برند — hue سازمانی + مقیاس روشنایی (۰..۱۰۰)
لایه ۲ (سمانتیک): --background/--foreground/--primary/--accent/--muted/--border/... (موجود)
                   + سه «خانواده ظاهری»: light / dark / high-contrast
                   + دو «حالت چگالی»: cozy / compact  ← G11
                   + یک «مقیاس تایپ»: font-size پایه ۱۲/۱۳/۱۴
لایه ۳ (کامپوننت): کلاس‌های tw از توکن لایه ۲ استفاده می‌کنند — مثل امروز؛
                   هیچ کامپوننتی رنگ خام نمی‌بیند (قاعده موجود پروژه)
```

اعمال: `class="dark cozy fs13 brand-terracotta"` روی `<html>` — یک آبجکت تنظیم per-user در `io.ui.v1:theme` + قفل `localStorage` برای فلِش اول (بدون فلش سفید در تم تاریک: اسکریپت کوچک قبل از هیدرات). برند رنگ per-company از ستون جدید `company.brandColor` (P2.8-T5) — پیش‌فرض تراکوتا هلدینگ.

## ۷. ماندگاری نشست — معماری GitHub + Neon (پاسخ دغدغه «برگشت محیط به حالت پیش‌فرض»)

مشکل: ایستگاه بازیابی محیط فقط تا آخرین **کامیت محلی** پایدار است و در بازگشت‌های سنگین حتی خود ایستگاه عقب می‌رود (رخداد ۱۴۰۵/۰۶/۰۹). راه‌حل دوبخشی:

```
کد   → GitHub (repo خصوصی)      : هر بسته = commit + push → قطعاً از sandbox مستقل
داده → Neon (Postgres ابری)      : DATABASE_URL خارج از دیسک sandbox → reset محیط بی‌اثر
```

1. **GitHub**: کارفرما repo خصوصی + توکن fine-grained (فقط همین repo، دسترسی Contents:read/write) می‌سازد؛ در sandbox: `git remote add origin` → `push -u origin main` پس از هر بسته؛ در شروع هر نشست: `git fetch && git status` برای اطمینان از همترازی. راهنمای گام‌به‌گام برای کارفرما (ساخت اکانت → repo → توکن) در §۷.۱ تحویل شده است.
2. **Neon** — ✅ اجرا شد (۱۴۰۵/۰۶/۱۰، بسته لایه سوم ماندگاری؛ جزئیات: RECOVERY-PLAN/worklog): پیکربندی Prisma به Postgres (provider فعلی SQLite است — مهاجرت با `prisma db pull/push` + اسکریپت انتقال داده seed)؛ مزیت جانبی: بکاپ زمانی و اشتراک بین نشست‌ها؛ ریسک: تأخیر شبکه — برای این حجم داده ناچیز.
3. **پروتکل نشست** (در AGENTS.md قواعد اجرایی ثبت شد):
   - **شروع هر نشست**: خواندن `worklog.md` آخرین ورودی + `git log --oneline -5` + سلامت سرور/db + تطبیق «آخرین وضعیت مکتوب» با دیسک؛ هر ناهماهنگی → گزارش به کارفرما قبل از کار.
   - **پایان هر بسته/نشست**: `bun run check` سبز → commit Conventional → (اگر ریموت فعال) push → ورودی worklog.
   - **الزام سخت**: هیچ بسته سبزِ بی‌کامیت رها نمی‌شود (درس رخداد ۰۶/۰۹).
4. بهداشت فوری اعمال‌شده در همین بسته: `.env` از git خارج شد (نگهداری `.env.example`) تا با اتصال Neon، راز اتصال هرگز وارد تاریخ git نشود.

### ۷.۱ راهنمای کارفرما — آماده‌سازی GitHub (خلاصه)

1. ثبت‌نام در github.com (ایمیل + رمز).
2. دکمه New repository → نام مثلاً `ideaone-erp` → **Private** → Create.
3. Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate: عنوان `sandbox-agent`، انقضا ۹۰ روز، Repository access = Only select repositories → همین repo → Permissions: **Contents = Read and write** → Generate → کپی توکن (فقط یک بار نمایش داده می‌شود).
4. ارسال توتن به همین گفتگو؛ بقیه (remote/push/pull) در sandbox انجام می‌شود. توکن قابل ابطال (Revoke) است و پس از پایان همکاری حذف شود.
5. Neon: neon.tech → ثبت‌نام → Create project → از Dashboard بخش Connection string را کپی و ارسال کن.
