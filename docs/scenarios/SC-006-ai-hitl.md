# SC-006 — دستیار هوشمند نامه با انسان در حلقه (HITL)

وضعیت: فعال | ماژول: letters (AI) | SPEC: `modules/letters/SPEC.md` §7-8 | بازنگری: ۱۴۰۵/۰۶/۰۵

## بازیگران

- **دبیر اداری** (dabir.arad): بهره‌بردار پیشنهاد و تأییدکننده
- **سرویس LLM** (z-ai-web-dev-sdk — فقط سرور)

## سیاست‌های ثابت (غیرقابل مذاکره)

1. نامه با محرمانگی **SECRET** هرگز به مدل نمی‌رود (چک سرور + پنل AI در UI جایگزین متن سیاست).
2. خروجی مدل **ذخیره نمی‌شود** مگر با کلیک صریح «تأیید و اعمال پیشنهاد».
3. فقط subject/type/sender/body به مدل می‌رود (نه متادیتای سازمانی اضافه).
4. پاسخ مدل JSON با ساختار ثابت؛ خارج از لیست طبقه‌بندی → سقوط امن به «اداری و هماهنگی».

## شاخه‌ها

| شاخه | رفتار |
|---|---|
| نامه SECRET | پنل AI حذف؛ متن: «برای نامه‌های «سری»، تحلیل هوش مصنوعی طبق سیاست داده غیرفعال است.» — تلاش مستقیم API: 403 با همان متن سیاست |
| مدل JSON خراب برگرداند | «پاسخ سرویس هوش مصنوعی قابل تفسیر نبود» |
| قطع سرویس LLM | 503 «سرویس هوش مصنوعی در دسترس نیست؛ لطفاً بعداً تلاش کنید» — نامه و گردشکار دست‌نخورده |
| طبقه‌بندی خارج لیست | پیش‌فرض «اداری و هماهنگی» (بدون خطا) |
| اولویت خارج «عادی/فوری» | قلاب به «عادی» |
| خلاصه/نکات بیش از حد | slice(600) / ۵ نکته |
| اعمال بدون category یا summary | «طبقه‌بندی و خلاصه الزامی است» |
| درخواست دوباره پس از اعمال | مجاز — پیشنهاد تازه؛ اعمال دوباره بازنویسی می‌کند (نسخه‌بندی پیشنهاد: P2-T15) |

## معیار پذیرش

- [ ] هیچ مسیری aiCategory/aiSummary را بدون AI_APPLY ثبت نمی‌کند.

- [ ] audit شامل AI_SUGGEST (درخواست) و AI_APPLY (اعمال) است.
